# Argos Translate 基準値計測結果

Issue #4 の結果。計測は `bench/argos_baseline.py` で行った。

## 1. 計測条件

| 項目               | 内容                                                                              |
| :----------------- | :-------------------------------------------------------------------------------- |
| 実行環境           | Linux、CPU 2コア(`cpu_count=2`)、CPU のみ                                         |
| Python             | 3.10.22                                                                           |
| argostranslate     | 1.11.0                                                                            |
| ctranslate2        | 4.8.3                                                                             |
| torch              | 2.14.1+cpu(CPU 専用索引。NVIDIA モジュールなし)                                   |
| テスト文           | 14文(短文4・通常文4・長文2・専門用語4)。`docs/testdata/sentences.json`            |
| 方式               | 全文を順に翻訳する周回を5回。各文の中央値を集計                                   |
| キャッシュ対策     | Argos は直前の段落をキャッシュするため、同一入力を連続させない周回方式にした      |

## 2. 速度・メモリ

| 指標                 | en→ja    | ja→en    |
| :------------------- | :------- | :------- |
| 初回起動(モデル読込) | 3.58 秒  | 7.67 秒  |
| 1文の中央値          | 0.756 秒 | 0.954 秒 |
| p95                  | 2.636 秒 | 2.819 秒 |
| 処理速度             | 95.7 文字/秒 | 37.5 文字/秒 |
| ピークメモリ         | 約618 MB | 約625 MB |

ピークメモリには `torch` と `stanza` の読み込み分を含む。モデル単体の値ではない。

| カテゴリ | en→ja 中央値 | ja→en 中央値 |
| :------- | :----------- | :----------- |
| short    | 0.394 秒     | 0.313 秒     |
| normal   | 0.756 秒     | 0.955 秒     |
| terminology | 1.098 秒  | 1.438 秒     |
| long     | 2.507 秒     | 2.512 秒     |

## 3. 時間の内訳(en→ja、`--profile`)

70回の翻訳呼び出しの合計 63.2 秒のうち、次のとおり。

| 区分                                   | 時間     | 割合   |
| :------------------------------------- | :------- | :----- |
| `apply_packaged_translation` の自己時間 | 61.0 秒  | 約96.5% |
| 文分割(stanza)                       | 2.05 秒  | 約3.2%  |

- 時間の大半は `apply_packaged_translation` の自己時間である。ここには CTranslate2 の推論呼び出しが含まれる。C++ 部分は cProfile では別行にならないため、推論とトークナイズの厳密な内訳は未分離。
- 文分割は主要なボトルネックではない。したがって Rust 化しても、推論側の速度は変わらない。
- 2コア環境の値であり、実際に使う機械のコア数での再計測が必要。

## 4. 品質(目視評価、評価者の主観)

| 方向  | ○  | △  | ✕  |
| :---- | :- | :- | :- |
| en→ja | 7  | 1  | 6  |
| ja→en | 9  | 0  | 5  |

- 通常文は両方向とも実用レベル。
- 短文・長文・専門用語では誤訳が出る(例: 「9時」→「9件」、「Thank you for your help」→「お問い合わせ」、「量子化」→「定量化」)。
- ja→en の出力に日本語の文字や壊れた語(`mis翻訳ing`、`This駐`、`is8ntized`)が混入する。トークナイズの不具合の疑いがあり、Rust 実装で SentencePiece まわりを移植する際の確認事項とする。
- 端末表示上の空白(`コ ピー` 等)は、80桁折り返しによる表示上のものと判断した。

## 5. G1 判定

**合格**。誤訳は許容範囲と判断する(判定者: xzyozi、2026-10-20)。

- 前提: 翻訳結果は参考訳として使い、誤訳が出うることを許容する。
- 前提が変わり、誤訳が許容できなくなった場合は、別モデル(例: NLLB-200 系)との比較を再検討する。
