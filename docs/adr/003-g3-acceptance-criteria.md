# ADR-003: G3(Rust と Argos の出力一致)の合格基準

| 項目           | 内容                  |
| :------------- | :-------------------- |
| ステータス     | accepted              |
| 決定日         | 2026-10-21            |
| 決定者・承認者 | tray-translate team   |
| 置換元ADR      | なし                  |
| 関連Issue      | #1, #8, #20, #21, #22 |

## 1. 背景・課題

判断ゲート G3 は「Rust コアの出力が Python(Argos Translate)と一致するか」を問う。これまでは 85% 超を根拠にした暫定合格で、比較の方法としきい値が文書化されていなかった。

- **背景**: 比較コマンド `tt bench <pair> docs/testdata/sentences.json --compare <py_bench.json>` は、各文について Rust と Python の出力を `trim` して完全一致で比べ、一致率を出す。
- **実測**: 検証機(Rocky Linux 8、x86_64、AVX/AVX2 なし)で同一マシン比較を行った。

  | 条件                                        |     en→ja     |     ja→en     |
  | :------------------------------------------ | :-----------: | :-----------: |
  | PR #19(入力末尾の EOS を付与しない修正)の前 | 6/14 (42.9%)  |    未計測     |
  | PR #19 の後                                 | 12/14 (85.7%) | 12/14 (85.7%) |

- **制約**:
  - 同じ構成(Argos 1.11.0、ctranslate2 4.8.3、CPU)でも、マシンが違うと Argos の出力が変わる文がある。Windows 開発機と検証機で、同じ入力に異なる訳が出た(例: short-02)。int8 量子化モデルが、CPU の命令セットや演算バックエンドの差に影響を受けると考えられるが、原因の切り分けは未了である(#22)。
  - テスト文は 14 文で、1 文の差が約 7.1% に当たる。
- **判断しない場合の影響**: 合格・不合格が担当者の解釈に依存し、回帰の検出と、フェーズ4 への移行判断ができない。

## 2. 決定

### 2.1 合格基準

言語ペアごとに、次の条件をすべて満たすとき G3 を合格とする。

- 一致率が **85% 以上**である。テスト文が 14 文の場合は、**12 文以上**が一致すること(11/14 = 78.6% は不合格、12/14 = 85.7% は合格)。
- 対象は、`docs/testdata/sentences.json` の全文とする。
- 対象の言語ペアは **en→ja と ja→en の両方**とする。それぞれが基準を満たすこと。

### 2.2 比較の方法

- 比較は `tt bench` の出力(`trim` した文字列の完全一致)に従う。
- **基準出力(Python 側)は、比較を実行するのと同じマシンで取得する。** 別のマシンで取得した基準出力とは比較しない。
- 基準出力は `bench/argos_baseline.py` で取得する(`--repeat 1` でよい)。
- Rust と Python は、同じモデルファイルを使う(`TT_MODEL_DIR` で Argos 導入済みのパッケージを指定してよい)。
- 比較時に記録する情報: マシン、OS、CPU の命令セット、Argos・ctranslate2 のバージョン、Rust 側のコミット、一致率、`[DIFF ]` の文。

### 2.3 判定の扱い

- 基準未満(不合格)のときは、差分を調べ、修正または本 ADR の見直しを行う。
- 基準を満たしていても、`[DIFF ]` の文は Issue(#22 など)で原因を追跡する。基準を満たすことと、原因が解決済みであることは別である。
- 翻訳の品質そのものは G1 で扱う。G3 は Rust 実装が Argos と同等に動くかを確認するゲートであり、品質を保証するものではない。

### 2.4 現在の判定

本基準を、2026-10-21 時点の結果に適用する。

| 言語ペア | 一致率        | 判定 |
| :------- | :------------ | :--- |
| en→ja    | 12/14 (85.7%) | 合格 |
| ja→en    | 12/14 (85.7%) | 合格 |

両ペアが基準を満たすため、**G3 は合格**とする。

## 3. 理由・代替案

### 採用理由

1. 完全一致(100%)を求めると、Rust 実装が正しくても、演算バックエンドの差で不合格になりうる。実際に、Python 同士でもマシンが違うと出力が変わった。
2. 修正前の 42.9% は、実際の不具合(入力末尾の EOS)を反映していた。85% の基準は、この規模の不具合を検出できる。
3. 同一マシン比較に限定すれば、環境差を取り除き、Rust 実装の差だけを見られる。
4. 既存の `tt bench` で、追加の実装なしに判定できる。

### 代替案

| 代替案                    | 利点                         | 欠点・リスク                                                             | 採用しなかった理由                                             |
| :------------------------ | :--------------------------- | :----------------------------------------------------------------------- | :------------------------------------------------------------- |
| 完全一致 100%             | 基準が単純                   | バックエンド差で不合格になり、回帰と区別できない                         | 実測で 100% に届かず、差の多くが許容できる言い換えだった       |
| BLEU や chrF など品質指標 | 言い換えを許容して比較できる | 14 文では統計的に不安定。評価ツールの追加が必要                          | 現時点では実装コストに見合わない。文数を増やすときに再検討する |
| 別マシンの基準出力と比較  | 基準を共有できる             | マシン依存の差が混ざる                                                   | 実測で、マシン間の差が確認されている                           |
| しきい値を 80%            | 余裕がある                   | 14 文では 12/14 が必要で、85% と判定が変わらない。文数を増やすと差が出る | 文数が少ない間は差が出ない。区切りのよい 85% を採用した        |
| しきい値を 90%            | 厳しい                       | 14 文では 13/14 が必要になり、現状の差(2 文)で不合格になる               | 原因が未確定の差で、先に進めなくなる                           |

## 4. 影響・トレードオフ

- **利点**: 判定が再現できる。回帰の目安になる。
- **欠点・コスト**:
  - 14 文では、1 文の差がしきい値を跨ぐ(12/14 が合格、11/14 が不合格)。判定が粗い。
  - 同一マシンで毎回 Python の基準出力を取り直す手間がかかる。
  - 検証機では、Python の実行に追加の指定が必要(`numpy<2.4`、環境によっては `OMP_NUM_THREADS=1 OMP_STACKSIZE=4M`)。
- **影響を受ける正本文書**: ロードマップ(#1)、引き継ぎ情報(#8)の G3 の記載。`docs/test/argos-baseline-result.md` の未実施項目「Rust 実装との出力一致比較(G3)」は、結果を別途記録するときに更新する。
- **移行・ロールバック**: 不要。基準を変える場合は後継 ADR を作る。
- **セキュリティ・運用上の影響**: なし。
