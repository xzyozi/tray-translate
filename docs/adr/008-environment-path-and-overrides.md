# ADR-008: 環境パスと設定上書きの実装整合性

| 項目           | 内容                |
| :------------- | :------------------ |
| ステータス     | accepted            |
| 決定日         | 2026-10-27          |
| 決定者・承認者 | tray-translate team |
| 置換元ADR      | なし                |
| 関連Issue      | #99（後半）         |

## 1. 背景・課題

ADR-002では、OS標準の保存先と `TT_*` による設定上書きを環境非依存方針として記録した。その後、実装とデータ構造・環境仕様の整理が進み、設定・履歴、モデル、ログの実際の扱いが当時の記述と異なることが明確になった。

- **設定・履歴**: `crates/app/src/paths.rs` は `TT_CONFIG_DIR` を優先し、未指定または空白の場合は `dirs::config_dir()/tray-translate` を使用する。設定と履歴は同じディレクトリに保存する。
- **モデル**: `crates/core/src/paths.rs` は `TT_MODEL_DIR` を優先し、未指定または空白の場合は `dirs::data_dir()/tray-translate/packages` を使用する。
- **ログ**: CLIは `RUST_LOG` を使う tracing subscriber を初期化する。GUIは tracing subscriber を初期化しない。
- **未実装の上書き項目**: `TT_LOG_LEVEL` と `TT_COMPUTE_TYPE` は現在のRust実装に存在しない。

ADRは判断理由の正本であり、現在仕様の正本ではない。現在仕様の正本は、永続化を `TT-DS-001`、環境・開発基盤を `TT-ENV-001`、システム全体の方針を `TT-BD-001` が担う。ADR-002の旧§2.4を現在仕様として解釈すると、既存利用者の保存先や実装のログ設定を誤って変更するおそれがある。

## 2. 決定

1. **現在仕様の根拠と正本を分離する**。現在仕様を整理するときは実装を確認済みの根拠とし、現在仕様の正本への記載は `TT-DS-001` と `TT-ENV-001` に委ねる。本ADRは実装・正本文書との整合を選んだ理由を記録し、仕様の詳細を複製しない。
2. **設定と履歴のパスは現行実装に合わせる**。`TT_CONFIG_DIR` が指定されている場合はそのディレクトリを使用し、未指定または空白の場合は `dirs::config_dir()/tray-translate` を使用する。設定と履歴のファイル名および保存契約の詳細は `TT-DS-001` を参照する。
3. **モデルのパスは現行実装に合わせる**。`TT_MODEL_DIR` が指定されている場合はそのディレクトリを使用し、未指定または空白の場合は `dirs::data_dir()/tray-translate/packages` を使用する。モデルパッケージの配置・構造の詳細は `TT-DS-001`、環境変数の扱いは `TT-ENV-001` を参照する。
4. **ログの環境変数は現行実装を記録する**。CLIは `RUST_LOG` と tracing subscriber を使用し、GUIは tracing subscriber を初期化しない。`TT_LOG_LEVEL` は現時点で実装せず、将来拡張の対象とする。
5. **推論計算タイプの環境変数は現時点で実装しない**。`TT_COMPUTE_TYPE` は将来拡張の対象として記録するが、現行仕様の設定項目にはしない。
6. **既存利用者の保存先移行を行わない**。本判断に伴うコード変更、既存ファイルの移動・変換、移行案内は実施しない。既存の保存先を変更する必要が生じた場合は、移行方法と互換性を別途決定する。

## 3. 理由・代替案

### 採用理由

1. 現行実装と既存利用者の保存状態を基準にすることで、文書更新だけを理由に保存先やログ設定を変更する回帰を避けられる。
2. 永続化の詳細を `TT-DS-001`、環境・開発基盤の詳細を `TT-ENV-001` に集約すると、ADRに現在仕様を重複記載せず、文書ごとのSSOT境界を維持できる。
3. `TT_LOG_LEVEL` と `TT_COMPUTE_TYPE` を未実装のまま明示することで、実装済みの機能と将来拡張の候補を混同しない。
4. 保存先の移行処理を追加しないことで、利用者の既存データを暗黙に移動・複製・削除するリスクを避けられる。

### 代替案

| 代替案 | 利点 | 欠点・リスク | 採用しなかった理由 |
| :----- | :--- | :----------- | :----------------- |
| 実装をADR-002に合わせて `LOCALAPPDATA` 基準のパスと `TT_*` の上書き項目を追加する | ADR-002の当時の方針と実装を一致させられる | 既存利用者の保存先が変わる。`TT_LOG_LEVEL` と `TT_COMPUTE_TYPE` の実装範囲も広がる | 現在の要件に実装変更の必要性がなく、既存利用者への影響を受け入れる根拠もないため |
| 既存保存先から新しい保存先へ移行する処理を実装する | 保存先を変更しても既存データを引き継げる | OSごとの移行元判定、失敗時の復旧、重複・権限エラーの扱いが必要になる | 本件の要件に移行処理はなく、既存利用者の保存先を変更するコード変更を行わないため |

## 4. 影響・トレードオフ

- **利点**: ADR-002の旧記述を判断時点の記録として残しながら、現在の実装と正本文書への参照を明確にできる。文書更新による保存先変更は発生しない。
- **欠点・コスト**: `TT_LOG_LEVEL` と `TT_COMPUTE_TYPE` は利用できない。将来実装する場合は、実装だけでなく `TT-DS-001` または `TT-ENV-001`、必要に応じて後継ADRを同じ変更単位で更新する必要がある。
- **影響を受ける正本文書**: `TT-DS-001` は保存先と永続化契約、`TT-ENV-001` は環境変数と開発・実行環境を定義する。`TT-BD-001` はシステム全体の方針を定義する。本ADRはこれらの詳細を上書きしない。
- **移行・ロールバック**: 移行処理は行わないため、今回の判断に伴う移行・ロールバックは不要である。将来保存先を変更する場合は、移行計画を決定してから実装する。
- **セキュリティ・運用上の影響**: 保存先、ログ出力、ネットワーク通信の動作は本判断によって変更しない。設定・履歴の内容や権限の詳細は `TT-DS-001` を参照する。

## 6. 例外・見直し条件

- **例外・適用差異**: ADR-002 §2.4のパスおよび `TT_*` の列挙は判断時点の記録であり、現在仕様として適用しない。
