# ADR-006: GUI のマルチプラットフォーム方針と日本語フォントの扱い

| 項目           | 内容                              |
| :------------- | :-------------------------------- |

| 決定者・承認者 | tray-translate team               |

## 1. 背景・課題

GUI の UI/UX 刷新（親 Issue #56）に着手するにあたり、残りの画面変更 Issue の壁打ちで方針を整理した。個別 Issue の実装判断が、GUI の移植性方針とぶつからないようにするため、共通の前提を記録する。

- **背景**: GUI は egui / eframe（ADR-004）で実装している。日本語フォントは `crates/gui/src/fonts.rs` が OS のフォントを探して登録し、見つからなければ日本語が四角（豆腐）になる。
- **要求・制約**:
  - GUI は Windows 実機での確認を完了条件とするが、設計上はマルチプラットフォームで動く GUI を目指す。
  - 翻訳推論は完全オフラインを守る（ADR-002 2.5）。
  - GUI は CI の対象外（#53）のため、実機でのスクリーンショット確認が品質ゲートになる。
- **判断しない場合の影響**: #59 のアイコン方式、#57 の言語選択、#62 のフォント実装がそれぞれ別の前提で進み、OS 依存の実装が混ざる。

## 2. 決定

### 2.1 マルチプラットフォーム方針

- GUI のコードは OS に依存しない形で書く。OS 固有の処理は、パス探索のような境界に閉じ込める。
- 配布と実機確認の対象は ADR-002 に従う（当面 Windows を実機確認の基準とする）。配布対象外の OS でも、コードを移植可能に保つ。
- 複数の案が成り立つ場合は、移植性を保てる案を選ぶ。

### 2.2 日本語フォント（#62）

- **フォントはバイナリに同梱しない**（案 D を採用）。
- OS ごとの探索パスを、Windows・macOS・Linux それぞれ用意する。Linux の探索パスは削除せず維持する。
- いずれのフォントも見つからない場合は、起動時のログとステータスで案内する（四角表示のまま黙らせない）。
- ジャギ（文字の粗さ）の原因はフォントとは限らない。フォントを変える前に、実機で `pixels_per_point` と高 DPI の設定を変えた前後を比較して原因を切り分ける。

### 2.3 画面仕様の判断

| Issue        | 判断                                                                                                                                                                                        |
| :----------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| #57 左右分割 | 幅 640px 以上で左右分割、未満で上下配置にする。                                                                                                                                             |
| #57 言語選択 | 導入済みモデルの `available_pairs` から作る。未導入の言語は選択肢に出さず、モデル管理タブへ案内する。                                                                                       |
| #57 入れ替え | 言語のみ入れ替える。原文・訳文のテキストは入れ替えない。入れ替えだけでは翻訳は走らせない。逆方向が未導入のときはボタンを無効化し、理由をツールチップで示す。                                |
| #59 アイコン | 字形（フォント依存）ではなく、図形描画（`Painter`）で用意する。ツールチップとキーボード操作（Tab 移動）を必須とする。                                                                       |
| #61 状態表示 | 状態を `Info / Busy / Error` の enum にし、色とアイコンを分ける。スピナー表示中だけ再描画を要求し、アイドル時の CPU 使用を増やさない。                                                      |
| #61 範囲     | 「モデル読み込み中」と「翻訳中」の区別は #61 に含めず、#75 で別管理する。                                                                                                                   |
| #60 自動翻訳 | 既定はオフ。デバウンスの初期値は 800ms とし、実測で調整する。古い結果はリクエスト ID で破棄する。自動翻訳が有効のときは自動コピーを無効にする。有効時は、言語の変更も入力の変更として扱う。 |

### 2.4 実装順序と PR 運用

#49 と #54 は完了済みで、前提を満たしている。残りは次の順序で実装する。

|  順   | Issue                | ブランチ                      | PR 本文の記載 | 順序の理由                                             |
| :---: | :------------------- | :---------------------------- | :------------ | :----------------------------------------------------- |
|   1   | #62 日本語フォント   | `feat/62-font-search-paths`   | `Closes #62`  | #59 のアイコン方式（図形描画）に影響するため先に決める |
|   2   | #57 左右分割         | `feat/57-side-by-side-layout` | `Closes #57`  | 以降の画面部品の配置先になる                           |
|   3   | #59 インラインボタン | `feat/59-inline-buttons`      | `Closes #59`  | #57 のエリア構造に重ねて配置する                       |
|   4   | #61 インジケーター   | `feat/61-status-and-spinner`  | `Closes #61`  | 状態 enum は #60 の前提になる                          |

- 5 本とも `crates/gui/src/app.rs` を変更するため、並列に進めると競合する。ブランチは直前のブランチから分岐し、**順番に積み上げる**。
- 各 PR は `main` を向ける。前の PR がマージされるまで、後続の PR には前の PR の差分も含まれる。レビューとマージは番号順に行う。
- 各 PR の本文に `Closes #N`（上表）を書き、マージ時に対応する Issue を自動でクローズする。親 Issue #56 は全サブ Issue の完了後に手動でクローズする（PR には `Refs #56` と書く）。
- 各 PR で `docs/test/gui-manual-test-guide.md` を更新する。実機（Windows）のスクリーンショットは、PR の作成後にレビュー担当が添付する。

## 3. 理由・代替案

### 採用理由

1. フォントを同梱しないことで、配布サイズ（README の約 18MB）を増やさず、ADR-002 の完全オフライン方針とも衝突しない。
2. 図形描画のアイコンは、フォント環境に左右されず、OS が変わっても同じ見た目になる。
3. 入れ替えで翻訳を走らせない設計は、自動翻訳（#60）が入る前後で挙動を揃えやすい。
4. 状態表示の enum 化は、見た目の整理に限定でき、core 側の変更を伴わない。

### 代替案

| 代替案                                    | 利点               | 欠点・リスク                                                      | 採用しなかった理由                                             |
| :---------------------------------------- | :----------------- | :---------------------------------------------------------------- | :------------------------------------------------------------- |
| フォントを同梱（Noto Sans JP など）       | どこでも同じ見た目 | 配布物が数 MB〜十数 MB 増える。OFL 1.1 のライセンス表記が必要     | 配布サイズの増加に見合う根拠が、現時点で実機から得られていない |
| 初回起動時にフォントを取得                | 配布物が軽い       | 完全オフライン方針（ADR-002）と衝突する                           | 方針違反                                                       |
| アイコンを絵文字・記号の字形で用意        | 実装が簡単         | egui 既定フォントに無い字形が多く、OS ごとに見た目が変わる        | 移植性を保てない                                               |
| 入れ替えでテキストも入れ替える            | DeepL と同じ挙動   | 再翻訳が走り、意図しない結果になりうる                            | 方針を単純に保つため。必要になれば後継 ADR で見直す            |
| 「モデル読み込み中」の区別を #61 に含める | 一度に実現できる   | core 側のイベント追加が必要で、#54 の責務整理と重なり範囲が膨らむ | #75 で別管理とした                                             |

## 4. 影響・トレードオフ

- **利点**: 配布サイズが増えない。画面仕様が Issue 間でぶれない。OS 依存の実装が混ざりにくい。
- **欠点・コスト**: フォントが見つからない環境では見た目が環境依存になる。OS 別の探索パスの保守が必要。
- **影響を受ける正本文書**: `docs/test/gui-manual-test-guide.md`（画面変更ごとに更新）、README の画面説明。
- **移行・ロールバック**: フォントの同梱が必要になった場合は、後継 ADR を作成して置き換える。
- **セキュリティ・運用上の影響**: フォントは読み取りのみで、ネットワーク通信は発生しない。

## 6. 例外・見直し条件

- **例外・適用差異**: ADR-002 は Linux GUI を配布しない方針だが、本 ADR では「配布はしないが、コードは移植可能に保つ」と解釈する。
- **見直し条件**: 実機でフォント未検出による四角表示が実際に発生した場合、またはジャギの原因がフォントと判明した場合は、同梱を再評価する。
- **見直し時期**: #62 の実機確認後
